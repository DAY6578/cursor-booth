# バックアップと引き継ぎ

Discordの画面には、サーバーの会話をまとめて書き出す安定した手順が、このキットの対象にはありません。残すものは、骨組みと、運営が確定した文面です。

## 手元に残すもの

次を、このキットとは別に、運営だけが開ける場所へ保管します。保管場所のアドレスやパスワードを、チャンネルとこのファイルには書きません。

- このキット一式（書き換えた文面が分かる版）
- 確定したルール、歓迎、受付、日程のテキスト
- ロールの表。名前、色、一覧の上下、サーバー権限の差
- チャンネルの表。カテゴリ、名前、見てよいロール、書いてよいロール
- サーバーテンプレートを作ったなら、そのリンク
- 今有効な招待リンクの本数と期限。リンクの文字列を、複数人のメモへばらまかない

テンプレートのリンクを開くと、新しいサーバーの骨組みを作れます。メッセージ、ピン留め、メンバー、参加禁止の一覧は戻りません。重要な案内は、テキストとしても残します。

## テンプレートの更新

1. 元のサーバーで、チャンネルかロールを直す。
2. サーバー設定のサーバーテンプレートを開く。
3. 同期（更新）を押す。
4. プレビューで、意図したチャンネルとロールだけが入っていることを確認する。
5. 大会のたびに増やす一時チャンネルは、同期の前に削除する。

テンプレートのメニューが無い場合は、上の二つの表を最新にすることがバックアップです。

## 招待が漏れたとき

1. サーバー設定の招待、または招待の一覧を開く。
2. 漏れたリンクを無効化する。一覧が無いときは、期限付きリンクの期限が切れるまで、問題のチャンネルを見る権限を狭める。
3. 必要な人へ、新しい期限付きリンクを個別に渡す。
4. 運営メモに、無効化した事実と日付だけを残す。リンクの全文は残さない。

## 引き継ぎ

運営を増やすとき、サーバーの所有権は移しません。最上位ロール（管理者または主催）を、必要な人だけに付けます。

渡す前のチェック:

- [ ] 渡す相手の表示名を、運営メモに書いた
- [ ] 相手に二段階認証があることを確認した。無い人には、BANとチャンネル削除を任せない
- [ ] ロールの並びを一緒に見た
- [ ] 運営メモの場所と、初動のファイル（`03-moderation-first-response.md`）を読んでもらった
- [ ] テンプレートの保管場所を口頭か、運営だけが見るチャンネルで伝えた。公開チャンネルには貼らない
- [ ] 進行中のタイムアウト、キック、未対応の相談を、記録の型で渡した
- [ ] 招待リンクを作り直し、古い無期限リンクを無効化した

所有権の譲渡は、サーバーを完全に手放すときだけです。譲渡すると、元の所有者は所有者ではなくなります。戻すには、新しい所有者の操作が必要です。メニューは、サーバー設定のメンバーから、相手を選んで譲渡、という名前であることが多いです。普段の引き継ぎでは使いません。

## 離れる人

運営が抜けるときは、次を終えてからロールを外します。

- [ ] その人だけが知っている招待リンクを無効化した
- [ ] その人の最上位ロールを外した
- [ ] 運営メモに、抜けた日付と、引き継いだ人の表示名を書いた
- [ ] テンプレートのリンクを、残る運営の保管場所だけで開けることを確認した

## サーバー設定で推奨する任意項目

サーバーの安全性設定に、「モデレーション操作に二段階認証を要求する」という項目があることが多いです。オンにすると、二段階認証が無い人は、キックや削除ができなくなります。運営が二人以上ならオンにしてください。項目が無い場合は、最上位ロールを渡す相手を、二段階認証がある人に限定します。
